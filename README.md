# OWH: OpenWebUI Hybrid

OWH adds Nick's OpenRouter account as a second backend to his local Open WebUI (Docker container `open-webui`, v0.13.3, host network, port 8080), next to the local Ollama (`127.0.0.1:11434`), so the model picker offers local and cloud models and each chat goes to the backend of the model chosen. The deliverable is a small Python CLI, `owh-openrouter` (standard library only at runtime), that stores a dedicated OpenRouter key, manages a curated model allowlist, and writes the OpenRouter connection into Open WebUI's stored config through its admin API (idempotent, with snapshot and `remove`), plus the docs for using, rotating and undoing it.

**Status:** in development. See [`OWH_IMPLEMENTATION_PLAN.md`](OWH_IMPLEMENTATION_PLAN.md) for the phase table and what is done.

## Privacy
Local (Ollama) models stay on the laptop. A chat with an OpenRouter model (shown with an `OR.` prefix) sends the conversation, attached files, RAG excerpts and web-search results to OpenRouter and the upstream model provider. Titles, tags and follow-up suggestions are generated by a local model, so they never go to OpenRouter (ADR-0005). Open WebUI identifies itself to OpenRouter as "Open WebUI" (`HTTP-Referer`/`X-Title`, ADR-0012); nothing personal is sent in headers.

## Commands
| Command | What it does |
|---|---|
| `owh-openrouter set-key [--from-file F] [--force]` | Read the dedicated key at a hidden prompt, check its format and validate it live (`GET /api/v1/key`), then store it in `~/.config/owh/openrouter.key` (0600) |
| `owh-openrouter models [--search TEXT] [--json]` | Show the allowlisted models with live prices ($/M in/out) and flag unknown IDs (exit 1). `--search` searches all OpenRouter models |
| `owh-openrouter apply [--dry-run] [--task-model ID]` | Sign in as admin and write the OpenRouter connection (prefix `OR`, `model_ids` = allowlist) and a local task model. Saves a snapshot before writing, then verifies. A re-run is a no-op |
| `owh-openrouter status [--json] [--no-login]` | Read-only: version, connections (keys redacted), task model, picker counts, key limit/usage, snapshots |
| `owh-openrouter remove [--snapshot F] [--delete-key]` | Restore what OWH changed from the earliest snapshot of this Open WebUI, then verify. The snapshot is kept |

Global options go before the command (`--webui-url`, `--openrouter-url`, `--state-dir`, `--config-dir`, `--timeout`, `--json`, `--allow-remote`). `apply`, `status` and `remove` take `--email` and `--password-stdin`.

**Exit codes:** 0 ok, 1 validation, 2 usage, 3 refused, 4 failed (nothing changed), 5 failed after a partial change (run `remove`).

Full walkthrough: [`docs/OWH_USER-GUIDE.md`](docs/OWH_USER-GUIDE.md).

## Development
```
uv sync        # create .venv from uv.lock (dev tools only; the tool has no runtime dependencies)
make check     # pytest (coverage gate 90 %), ruff check, ruff format --check, shellcheck, gitleaks
make test-testbed   # OWH_TESTBED=1: apply -> no-op apply -> remove on a throwaway Open WebUI (about 45 s)
uv run owh-openrouter --help
```
`make check` needs `shellcheck` and `gitleaks` on `PATH`. Run `git config core.hooksPath scripts/git-hooks` once per clone. `make install` writes the launcher `~/.local/bin/owh-openrouter` (an OS modification, installed in Phase 05; run it from the main checkout).

Rehearsals use a throwaway Open WebUI: `scripts/owh-testbed.sh up|status|token|down|reset` (container `owh-test-owu`, volume `owh-test-owu-data`, `http://127.0.0.1:18080`; `down` removes the container, volume and its state dir). It never touches the live `open-webui`.
