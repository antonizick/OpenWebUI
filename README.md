# OWH: OpenWebUI Hybrid

OWH adds Nick's OpenRouter account as a second backend to his local Open WebUI (Docker container `open-webui`, v0.13.3, host network, port 8080), next to the local Ollama (`127.0.0.1:11434`), so the model picker offers local and cloud models and each chat goes to the backend of the model chosen. The deliverable is a small Python CLI, `owh-openrouter` (standard library only at runtime), that stores a dedicated OpenRouter key, manages a curated model allowlist, and writes the OpenRouter connection into Open WebUI's stored config through its admin API (idempotent, with snapshot and `remove`), plus the docs for using, rotating and undoing it.

**Status:** in development. See [`OWH_IMPLEMENTATION_PLAN.md`](OWH_IMPLEMENTATION_PLAN.md) for the phase table and what is done.

## Privacy
Local (Ollama) models stay on the laptop. A chat with an OpenRouter model (shown with an `OR.` prefix) sends the conversation, attached files, RAG excerpts and web-search results to OpenRouter and the upstream model provider. Titles, tags and follow-up suggestions are generated by a local model, so they never go to OpenRouter (ADR-0005). Open WebUI identifies itself to OpenRouter as "Open WebUI" (`HTTP-Referer`/`X-Title`, ADR-0012); nothing personal is sent in headers.

## Development
```
uv sync        # create .venv from uv.lock (dev tools only; the tool has no runtime dependencies)
make check     # pytest, ruff check, ruff format --check, shellcheck, gitleaks
uv run owh-openrouter --help
```
`make check` needs `shellcheck` and `gitleaks` on `PATH`. Run `git config core.hooksPath scripts/git-hooks` once per clone. `make install` writes the launcher `~/.local/bin/owh-openrouter` (an OS modification; not used before Phase 05).

Rehearsals use a throwaway Open WebUI: `scripts/owh-testbed.sh up|status|token|down|reset` (container `owh-test-owu`, volume `owh-test-owu-data`, `http://127.0.0.1:18080`; `down` removes the container, volume and its state dir). It never touches the live `open-webui`.
